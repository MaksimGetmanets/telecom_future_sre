# Дашборды как код

Каждый `*.json` в этой папке при `make up` (или `terraform apply`) попадает в Grafana автоматически.

| Файл | Что показывает |
|---|---|
| `demo-shop-slo.json` | SLI: доступность, ошибки 5xx, latency p50/p95/p99, доля быстрых запросов, burn rate бюджета ошибок. Цель SLO задаётся переменной сверху (черновик, финальные значения у PM) |
| `demo-shop-health.json` | Поды, рестарты, heap/CPU/GC, соединения с БД и логи того же сервиса из Loki |

## Как добавить или изменить дашборд

1. Правим дашборд в Grafana (она доступна на `kubectl -n monitoring port-forward svc/kps-grafana 3000:80`).
2. *Dashboard settings → JSON Model → Copy*, вставляем в файл здесь (поле `uid` не менять).
3. `terraform apply` в `terraform/` (или `make up`). Правки только через интерфейс пропадут при следующем применении.

## Допущения

- SLI считаются по бизнес-ручкам `uri=~"/orders.*"`, лейбл `application` и бакеты (0.1, 0.3, 0.5, 1, 2 с) из `apps/README.md`.
- Квантили p95/p99 оцениваются по бакетам, поэтому точны на границах бакетов. Порог 300 мс совпадает с бакетом `le="0.3"`.
- Логи ищутся по лейблам Alloy `namespace="demo"` и `app=<сервис>`.
